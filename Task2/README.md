### Контейнеры и их ответственность

| Компонент                    | Данные / задача                                             |
|------------------------------|-------------------------------------------------------------|
| Customer Portal + Mobile     | запись, документы, результаты анализов, история             |
| Staff Portal                 | ресепшен, врач, кассир, склад                               |
| API Gateway                  | контроль, проверки, доступ к API                            |
| IAM (Keycloak)               | субъекты, роли, MFA, жизненный цикл                         |
| Policy Decision Point        | ABAC/RBAC: patient ownership, doctor assignment, purpose    |
| Patient/CRM Service          | базовые ПДн, контакты                                       |
| Appointment Service          | расписание, статусы, филиал                                 |
| Medical Record Service       | диагнозы, исследования, заключения                          |
| Payment + 1C Adapter         | транзакция, ККМ, проводки                                   |
| Lab Adapter                  | внешний обмен анализами                                     |
| Notification Service         | напоминания, подтверждение/отмена                           |
| Audit + SIEM                 | расследование, detection                                    |
| KMS/Vault                    | ключи и секреты                                             |
| Change Data Capture Platform | сбор измений из БД/S3, обезличка, токенизация, анонимизация |
| BI / ML / LLM DB             | данные для BI, ML, LLM                                      |
| Analytic Platform            | платформа предоставления аналитики                          |

Внимание, на схеме приведен 1 контейнер Postgres, но разные домены хранятся в разных схемах/БД и изолированы друг от друга. 
Аналогично для BI / ML / LLM DB и Analytic Platform, там может быть более 1 контейнера, но изобразил 1, чтобы
не усложнять схему.


### Аналитический слой
1) Сбор данных из разрешённых источников по отдельным сервисным аккаунтам(ТУЗ), проверка схемы, антивирусный контроль 
файлов, регистрация lineage.
2) Restricted/raw: шифрование, KMS, TTL согласно законов, запрет BI-пользователям прямого чтения.
3) Privacy Processing: удаление ненужных колонок, токенизация идентификаторов, обезличивание, агрегирование редких 
комбинаций.
4) Curated/serving: ClickHouse/витрины только с утверждёнными наборами, row/column policies, query audit, запрет 
несанкционированных экспортов.
5) BI/ML/AI: минимальные dataset для обучения; доступ по цели и проекту; запрет сырой PHI в промптах, логах, embeddings и 
обучающих выборках по умолчанию. Регистрация модели, проверки на запоминание и утечки. Внешние LLM-провайдер — отдельная 
оценка обработки и передачи данных, по умолчанию недоступен для PHI.
6) Catalog + Lineage отслеживает производные данные. Удаление/ограничение обработки распространяется на downstream-копии
 и переобучение моделей по оценке юридических оснований и технической реализуемости.
