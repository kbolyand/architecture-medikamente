# Задание 4. Узкие места при миграции

При переходе от Excel, файловых баз 1С и общего Windows-сервера к новой платформе основной риск - не только потеря 
данных, но и замедление записи на приём, ошибок оплаты и недоступности медицинских карт. Особенно это важно при открытии 
филиалов и пятикратном росте объёма данных.

## Возможные узкие места

| Категория      | Возможная проблема                                                     | Последствия                                    |
|----------------|------------------------------------------------------------------------|------------------------------------------------|
| Инфраструктура | Один физический сервер, ограниченные CPU/диски, сеть между филиалами   | Простой сервисов, медленная работа в часы пик  |
| Данные         | Excel, сканы и файловые базы 1С; дубли, ошибки и разный формат записей | Долгий импорт, потери и некорректные данные    |
| Интеграции     | Устаревшие ККМ/OLE, обмен с 1С и будущей лабораторией                  | Очереди запросов, тайм-ауты, повторные платежи |
| Приложения     | Ручная бизнес-логика, синхронные вызовы, неудачное разделение сервисов | Рост задержек, каскадные ошибки                |
| Персонал       | Всего три IT-специалиста, мало опыта эксплуатации новой платформы      | Долгое устранение сбоев, ошибки внедрения      |
| Процессы       | Нет отработанного плана миграции и нагрузочного тестирования           | Длительный простой, сложный откат              |

## Что предлагаю сделать

| Приоритет | Мера                                                                           | Результат                                   |
|-----------|--------------------------------------------------------------------------------|---------------------------------------------|
| P1        | Провести инвентаризацию данных, очистку дублей и пробную миграцию              | Поймём качество данных и время переноса     |
| P1        | Мигрировать поэтапно: сначала запись пациентов, затем медкарты и платежи       | Меньше рисков для действующего офиса        |
| P1        | Настроить резервные копии, сценарий отката и тест восстановления               | Возможность быстро вернуть систему в работу |
| P1        | Провести нагрузочное тестирование на 5× текущей нагрузки с запасом на пики     | Выявим ограничения БД, API и сети заранее   |
| P2        | Сделать адаптеры к 1С/ККМ, очереди, тайм-ауты и идемпотентность платежей       | Сбои интеграций не остановят всю систему    |
| P2        | Добавить мониторинг: latency, ошибки, CPU, диск, соединения БД, длина очередей | Узкие места будут видны до массовых жалоб   |
| P2        | Обучить команду и привлечь DevOps/DBA на период миграции                       | Быстрее реагировать на проблемы             |

Я бы не стал сразу переносить всю систему в микросервисы. Для MVP достаточно выделить сервис записи и общий контур 
авторизации, а старую 1С оставить за адаптером. Так проще проверить работу с реальными пациентами и не останавливать 
бухгалтерию.
