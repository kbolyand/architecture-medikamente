#### Механизм тегирования данных
Предлагаю 2 независимых атрибута:
1) sensitivity_level — уровень конфиденциальности от низкого к самомум высокому:
- PUBLIC: Публичные данные, доступные всем,
- INTERNAL:	Внутренние данные организации,
- CONFIDENTIAL:	Конфиденциальные данные, доступные ограниченному кругу сотрудников,
- RESTRICTED: Особо чувствительные данные, требующие строгого контроля доступа и дополнительных мер защиты.
2) data_tags — тип информации:
- PATIENT_PII, 
- PATIENT_PHI, 
- PAYMENT_DATA, 
- EMPLOYEE_PII, 
- INVENTORY_DATA.

<b>Инструменты для тегирования данных</b>:
1) Уровень БД и файлов. Для классификации информации предлагается использовать метаданные, в которых указывается уровень 
чувствительности данных. Например, в PostgreSQL можно добавлять комментарии к колонкам через COMMENT, а также 
использовать специализированные каталоги данных для хранения и управления тегами, например, Data Catalog (DataHub)
2) Уровень API. Теги можно указывать непосредственно в OpenAPI спецификациях, например x-data-classification: PATIENT_PHI. 
На основании этих тегов API Gateway или другой компонент обработки ответов сможет определять, какие поля необходимо 
скрывать или маскировать или вызывать ошибку получения несанкционированных данных в зависимости от прав пользователя. 
3) Уровень каталога данных - Data Catalog. Предлагается создать единый реестр данных, в котором будет храниться 
информация об их расположении, уровне чувствительности и использовании. Это позволит отслеживать перемещение 
конфиденциальных данных между системами и контролировать соблюдение политик безопасности на всём пути обработки информации.
